legal-dd-verify

A data-driven legal due-diligence document verification & supplement-request pipeline

→ 中文版本

CI: GitHub Actions License: MIT Python 3.11 / 3.13 Offline · zero pip

legal-dd-verify reads a due-diligence checklist and a virtual data room (VDR), verifies document provision item by item, detects cross-file contradictions, generates supplement requests and key-issue memos, and emits 4 machine-readable deliverables. The whole pipeline runs offline with zero installation: dependencies are vendored in vendor/, so no pip install and no network access are required at runtime.

This repository is a complete, runnable worked example (reference implementation) bound to an originally synthesized fictional demo data room ("Yunqi Zhilian Technology Co., Ltd.") and a generic checklist. All entities, people, contracts, accounts, addresses, and transaction data are synthetic, and are unrelated to any real party, real project, or third-party question bank.

What problem it solves

The most underestimated workload in due diligence is reconciling a pile of PDF / XLSX / DOCX materials from the target company against a long checklist, line by line:

  • Was this document provided? To what extent (satisfied / partially satisfied / not satisfied)?
  • Do different files contradict each other? (articles say 10% equity, the ledger says 8%; the privacy policy says no cross-border data transfer, yet the cloud bill shows a Singapore node holding personal data)
  • Which claims / disputes were omitted from the dispute list?
  • Which documents are still missing and need a supplement request?

legal-dd-verify turns these steps into a reproducible pipeline, so lawyers can focus on "judgment and negotiation" rather than "flipping files and filling forms."

Pipeline structure

Switchable demo data rooms

The engine is data-driven: a demo data room is just a synthetic document set conforming to the schema; switching it makes the same engine re-derive every conclusion. Two fully independent, proper-noun-disjoint synthetic data rooms are bundled — cloudlink (Yunqi SaaS) and hanwei_semi (Hanwei Semiconductor / AI chips) — each with its own three planted structural issues.

Quick start

# After clone — no pip install, no network
cd legal-dd-verify

# End-to-end run (extract -> analyze -> render -> verify) — default scenario
python3 pipeline/run.py --scenario cloudlink --out out --verify

# Switch to the semiconductor scenario (self-contained under scenarios/hanwei_semi/)
python3 pipeline/run.py --scenario scenarios/hanwei_semi --out out2 --verify

# Offline smoke test (same command as GitHub CI; covers every bundled scenario)
python3 tests/smoke_test.py

Expected output includes RESULT: PASS: 52 unique items, 3 structural contradictions, 4 core-risk categories fully covered, 0 unresolved citations (for every scenario).

Honest boundaries

  • This repo is a methodology worked example bound to an original synthetic demo data room; the demo data room is unrelated to any real party / project / third-party question bank.
  • Output is lawyer-supportive analysis, not an independent legal opinion, and does not replace independent verification against registries, authorities, and counterparties.
  • The engine is bound to the demo data room's document structure; using it on real projects with different structures requires extending fact extraction and contradiction rules. It is not an "out-of-the-box generic product."
