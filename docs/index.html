legal-dd-verify

法律尽职调查资料核验与补件反馈流水线 · A data-driven legal due-diligence verification pipeline

CI: GitHub Actions License: MIT Python 3.11 / 3.13 Offline · zero pip

English version →

legal-dd-verify 读取一份尽职调查核查清单与一个虚拟资料室（VDR）， 逐项核验资料提供情况、识别跨文件矛盾、生成补件问询与重点问题，并输出 4 件机器可读交付物。 整条流水线离线运行、零依赖安装：依赖已随包 vendored 于 vendor/， 运行期无需 pip install、无需联网。

本仓库是一个完整、可运行的工作示例（reference implementation），绑定一份 从零原创的虚构演示数据室（"云栖智联科技股份有限公司"）与一份通用核查清单。 全部主体、人员、合同、账号、地址与交易数据均为合成信息，与任何真实主体、真实项目或第三方题库无关。

它解决什么问题

尽职调查里最容易被低估的工作量，是把目标公司扔过来的一大堆 PDF / XLSX / DOCX 资料， 和一份长长的核查清单，逐条对上：

  • 这份资料提供了没有？提供到什么程度（已满足 / 部分满足 / 未满足）？
  • 不同文件之间说法是否打架？（章程写持股 10%、台账写 8%；隐私政策说无数据出境、云账单却显示新加坡节点含个人信息）
  • 哪些索赔 / 争议被漏列进争议清单？
  • 还缺哪些资料、需要向对方发补件问询？

legal-dd-verify 把这些动作固化成一条可复现的流水线，让律师把精力放在"判断与谈判"上，而不是"翻文件和填表"上。

流水线结构

阶段模块职责
抽取pipeline/extract.py读取 PDF / XLSX / DOCX（或离线 .txt 抽取视图），按稳定的 XX.Y 文档前缀建立资料库
分析pipeline/analyze.py52 项核验 + 结构化跨文件矛盾检测（非写死答案）
渲染pipeline/render.py生成 4 件交付物
校验pipeline/verify.py独立校验器，反向解析引用、校验枚举与核心风险覆盖
编排pipeline/run.py串联四层引擎，支持 --verify 自检

流水线示意图

交付物

文件内容
尽调清单核验与反馈表.xlsx52 项逐条核验：状态 / 事实摘要 / 证据定位（精确到文件）/ 资料缺口 / 风险等级 / 处置类型 / 是否需人工复核
补件问询清单.xlsx去重后的补件问询，含类型与依据
重点问题摘要.docx交易及审阅范围 / 执行摘要 / 跨文件矛盾 / 核验统计 / 重点问题 / 优先补件与下一步
result_manifest.json机器可读清单：items / key_issues / cross_file_contradictions

快速开始

# 克隆后，无需 pip install、无需联网
cd legal-dd-verify

# 端到端运行（抽取 → 分析 → 渲染 → 校验）
python3 pipeline/run.py \
  --input materials \
  --checklist checklist/checklist_52.json \
  --out out \
  --verify

# 仅运行离线冒烟测试（GitHub CI 同款命令）
python3 tests/smoke_test.py

期望输出包含 RESULT: PASS：52 项唯一、3 处结构矛盾、4 类核心风险全覆盖、0 未解析引注。

诚实边界

  • 本仓库为方法论可运行示例，绑定原创合成演示数据室；演示数据室与任何真实主体 / 项目 / 第三方题库无关。
  • 输出为律师支持性分析，非独立法律意见，不替代对登记机关、主管机关及相对方的独立核验。
  • 引擎绑定演示数据室文档结构；用于不同文档结构的真实项目需扩展事实抽取与矛盾检测规则。它并非"开箱即用的通用产品"。
